# 0.1.0a10 — concurrent retrieval cache construction

This maintenance release fixes a race when independent callers first build
the same SQLite FTS5 retrieval index concurrently. Previously, one caller
published the index and the others could fail with `FileExistsError`.

The first complete index is still published atomically. Other callers reopen
it and verify its corpus identity. An index from a different corpus is rejected;
existing files are never overwritten. Temporary build files are cleaned up.

Regression tests cover same-corpus and different-corpus interleavings. A real
four-caller SQLite construction check on Linux reproduces the previous failure
and verifies successful concurrent construction with identical retrieval output.
This is a storage-concurrency test, not a new model-quality or full compatibility
matrix evaluation. Algorithms, model budgets, scoring and existing results are
unchanged.

Upgrade with `python -m pip install --upgrade agentinputlab==0.1.0a10`.
